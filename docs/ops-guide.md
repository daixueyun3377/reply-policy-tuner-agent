# 回复策略调优 Agent — 运营使用指南

> 面向 BOSS 直聘自动回复的运营同学。不需要懂代码，用自然语言描述想改什么即可。

---

## 一、它能帮你解决什么困难？

日常运营中，你可能遇到过这些情况：

| 以前的困扰 | 现在怎么做 |
|-----------|-----------|
| 想微调回复语气、提问方式，只能找技术改配置，来回沟通慢 | **直接用中文说**「语气收敛一点」「一次只问一个问题」，Agent 帮你改 |
| 改完不知道实际话术会变成什么样，只能上线碰运气 | **改之前先看对比**：同一条候选人消息，展示修改前后的回复差异 |
| 担心改出问题（过度承诺、编造门店/薪资、语气太热情） | **自动安全评估**：系统会检查硬规则、事实准确性、回复质量，有问题会拦下来 |
| 怕策略被悄悄改掉、改错了找不回来 | **必须你确认才生效**；每次修改有记录，也可一键恢复默认 |
| 管理员要帮多位运营同事调策略，不知道谁是谁 | 管理员 Token 下可先选定要服务的运营账号，再走同样流程 |

**一句话总结**：这是一个「带安全闸门的策略修改助手」——你提需求，它帮你校验、预览、评估，**只有你明确说「确认保存」才会真正写入**。

---

## 二、你需要准备什么？

### 运营同学（日常使用）

- 已安装 **Cursor** 或 **Trae** 等 AI 对话工具（推荐 Cursor）
- 技术同事已完成下方「安装与配置」（你只需会对话）
- 你的 BOSS 直聘账号已在浏览器登录（评估时会用到，用于匹配你的招聘身份）

### 技术同事（首次安装，一次性）

| 项目 | 要求 |
|------|------|
| 花卷 CLI（roll） | `npm install -g @roll-agent/core` |
| Node.js | ≥ 22.6.0 |
| 访问 Token | 向技术负责人申请 Reply Authority Service 的 Token |

**Token 分两种**（技术配置时会用到，运营只需知道自己是哪种权限）：

- **Client Token（客户端令牌）**：只能管理**自己**的策略
- **Admin Token（管理员令牌）**：可以管理**多位运营人员**的策略

## 三、安装与配置（技术同事操作）

### 1. 安装 Agent

```bash
roll agent install @roll-agent/reply-policy-tuner-agent
```

### 2. 写入配置

在项目根目录或 `~/.roll-agent/` 下的 `roll.config.yaml` 中添加：

```yaml
agents:
  env:
    reply-policy-tuner-agent:
      REPLY_AUTHORITY_URL: https://reply-authority.duliday.com
      REPLY_AUTHORITY_BEARER_TOKEN: 你的Token
      REPLY_AUTHORITY_TIMEOUT_MS: "120000"
```

> `TIMEOUT_MS` 设为 120 秒，是因为安全评估需要一定计算时间，避免中途超时。

### 3. 验证安装成功

```bash
roll run reply-policy-tuner-agent diagnostic_status --json
```

看到返回里有你的账号权限信息（`tenantIds`、scopes），说明安装成功。把结果截图发给运营同学，或确认运营能在 Cursor 里正常对话即可。

### 4. 在 Cursor 里启用（运营同学）

1. 打开 Cursor，确保工作区指向已配置 `roll.config.yaml` 的项目
2. 在对话里直接用中文描述需求（见下文「常见场景」）
3. 若 Cursor 未自动识别 Agent，可 @ 相关 skill 或让技术确认 `roll agent list` 中能看到 `reply-policy-tuner-agent`

## 四、能做什么？

| 你想做的事 | 怎么说（示例） |
|-----------|---------------|
| 查看当前策略 | 「帮我看一下现在的回复策略」 |
| 调整语气 | 「回复太热情了，改成更自然克制的，别用『太棒了』这类词」 |
| 改提问方式 | 「现在一次问太多，改成每次只问一个最关键的问题」 |
| 加保护规则 | 「候选人说具体时段有空时，直接确认覆盖，别反问『是指 X 之前还是之后』」 |
| 看修改效果 | Agent 会自动展示「修改前 vs 修改后」话术对比 |
| 安全评估 | Agent 自动执行，你只需看结果 |
| 确认保存 | 评估通过后，你说「确认保存」才会写入 |
| 恢复默认 | 「把我的策略全部重置回默认」（高危，会二次确认） |

**它不会做的事**：不会代替你发消息给候选人、不会操作 BOSS 网页聊天界面（评估时会借助浏览器读取你的 BOSS 账号名，但不发消息）。

## 五、策略与话术库：你能改什么？

自动回复策略不是一段固定话术，而是一套**分层配置**。你可以把它理解成：先定「怎么说」（人设 + 行业话术），再定「每个阶段怎么推进」（阶段策略），最后用「保护规则 + 事实核查」兜底。

对 Agent 说「帮我看一下现在的回复策略」，它会用白话展示当前配置要点；下面是你能主动修改的**完整清单**。

### 5.1 策略全景（六大模块）

| 模块 | 管什么 | 日常是否常改 | 你怎么说 |
|------|--------|-------------|---------|
| **回复人设** | 语气、热情、提问方式、称呼等 | ⭐ 最常改 | 「语气收敛一点」「一次只问一个问题」 |
| **阶段策略** | 初次接触、加微信、确认资格等各阶段怎么聊 | ⭐ 常改 | 「初次接触别急着推微信」「岗位咨询先概括再细问」 |
| **行业话术库** | 行业背景、常用词、禁忌词、写作指引 | ⭐ 常改 | 「加一条禁忌：别说包过」「引导话术里别出现门店字眼」 |
| **保护规则** | 绝对不能碰的红线（如编造薪资、过度盘问） | 偶尔改 | 「加一条规则：候选人说有空时段就直接确认」 |
| **事实核查** | 没有证据时能不能说具体数字/门店/城市 | ⚠️ 慎改 | 一般不改；有问题先联系技术 |
| **资格与输出护栏** | 年龄怎么处理、单条最多问几个问题 | 偶尔改 | 「年龄已知就别重复问」「审查感话术再屏蔽一些」 |

图例：**⭐ 常改** = 运营日常可提需求；**⚠️ 慎改** = 能改但会触发更严格评估或二次确认，建议先和技术对齐。

---

### 5.2 回复人设（决定「整体怎么说」）

| 配置项 | 含义 | 示例（当前默认风格） | 你可以怎么说 |
|--------|------|---------------------|-------------|
| 语气 | 整体说话风格 | 口语化自然聊天，不用客套话 | 「别那么官方，再口语一点」 |
| 热情程度 | 热络还是克制 | 高 | 「热情程度降一点，别过度夸赞」 |
| 幽默感 | 是否开玩笑 | 低 | 「保持严肃，不要玩梗」 |
| 回复长度 | 短 / 中 / 长 | 简短（1～2 句为主） | 「回复再短一点，别写小作文」 |
| 提问方式 | 一次问几个、什么时候追问 | 有意向时不追问、直接引导加微信；纯打招呼只做轻量方向确认 | 「一次只问一个最关键的问题」 |
| 共情策略 | 怎么回应候选人关切 | 直接回应核心问题；不重复问页面已有信息；薪资福利不做确凿承诺 | 「候选人问了薪资，先共情再引导加微信细聊」 |
| 称呼方式 | 怎么称呼对方 | 不称呼姓名，直接用「你」 | 「可以偶尔用『亲』吗」/「不要用昵称」 |
| 身份定位 | 你扮演什么角色 | 直接了当的招聘专员，说话不绕弯 | 「更像门店店长在招人，别太像 HR 审简历」 |
| 公司背景 | 业务类型一句话 | 连锁餐饮招聘 | 「我们是零售连锁，背景描述改一下」 |

---

### 5.3 阶段策略（决定「每个聊天阶段怎么推进」）

对话会按阶段切换目标。每个阶段都有四类可改内容：

| 子项 | 含义 |
|------|------|
| 阶段说明 | 这个阶段在聊什么（内部描述） |
| 主要目标 | 这一阶段最想达成什么 |
| 成功标准 | 怎样算聊得不错 |
| **推进策略** | **最关键**：这个阶段具体怎么引导（最常改） |
| 禁止行为 | 这个阶段绝对不能做的事 |

六个固定阶段：

| 阶段 | 典型场景 | 推进策略示例（节选） | 你可以怎么说 |
|------|---------|----------------------|-------------|
| **初次接触** | 候选人刚打招呼、第一次来问 | 有意向就直接引导加微信；纯打招呼只做全职/兼职方向确认，同一条里不推微信 | 「初次接触别一次问太多」 |
| **加微信** | 已经在聊，要转到私域 | 自然提出加微信发资料；引导时不提门店、城市 | 「加微信话术再自然一点，别像推销」 |
| **确认资格** | 判断候选人是否匹配 | 已有意向就引导加微信细聊，不在平台上逐项盘问年龄经验 | 「别在 BOSS 上像审简历一样连问四个问题」 |
| **岗位咨询** | 问薪资、排班、工作内容 | 先正面回答当前问题；没追问时不主动报过细数字和地址 | 「问排班时先概括，别一次甩完整班次表」 |
| **约面试** | 定时间、定到店 | 给出明确下一步，但问题数量要克制 | 「约面试时先确认对方哪天方便」 |
| **入职跟进** | 促到岗、回访 | 说明下一步与提醒，保持简洁 | 「跟进语气温和一点，别催太紧」 |

每个阶段的**禁止行为**也可以增删，例如：

> 加一条禁止行为：候选人消息里已经写了年龄，就不要再追问是否成年。

### 5.4 行业话术库（重点：行业怎么说）

**话术库**（系统里叫「行业话术」）是一套**行业专用的表达模板**，和人设配合使用：人设定基调，话术库定**行业用词、禁忌和写作习惯**。

当前默认有一套「餐饮连锁招聘」话术（你的账号若已自定义，以 Agent 查到的为准）：

#### 话术库结构

| 字段 | 含义 | 当前示例 | 你可以怎么说 |
|------|------|---------|-------------|
| **名称** | 这套话术的名字 | 餐饮连锁招聘 | 「把名称改成零售门店招聘」 |
| **行业背景** | 行业特点一句话 | 门店密集、排班灵活、强调稳定出勤 | 「我们是便利店，背景改成强调夜班和就近」 |
| **常用行业词** | 鼓励使用的词 | 排班、到岗、门店、班次 | 「常用词加上『提成』『保底』」 |
| **风格关键词** | 希望呈现的气质 | 直接、清晰、可信、自然 | 「风格关键词加上『亲和』，去掉『直接』」 |
| **禁忌用语** | **绝对不要出现的词/句** | 包过、绝对、随便都行、你是否满足岗位基本入职要求、身份证能不能正常上岗 | 「禁忌用语加上『太棒了』『非常不错』」 |
| **写作指引** | 具体怎么写的条目清单 | 见下方完整列表 | 「指引里加一条：引导加微信时严禁提门店地点」 |

#### 当前默认「写作指引」全文（可逐条修改）

1. 先解决当前问题，再推进下一步  
2. 避免像表单一样连续追问  
3. 避免资格审查感  
4. 候选人有具体意向时优先引导加微信进行详细沟通；纯打招呼无方向时先做轻量方向确认  
5. 引导加微信时只说加微信发资料细聊，**严禁**使用门店、店、区域、城市、附近、周边、匹配到哪个店等地点类词汇  
6. 识别 BOSS 一键发送模板：候选人首条若为平台自动生成格式（含「您发布的 XXX 职位」模式），岗位名不作为候选人本人选择，优先以候选人后续自己输入的内容判断真实方向  

#### 话术库修改示例

| 你的需求 | 对 Agent 说 |
|---------|------------|
| 禁止过度夸赞 | 「在行业话术库的禁忌用语里加上：太棒了、非常不错、超级棒」 |
| 加微信别说地点 | 「写作指引里强调：引导加微信时不要出现任何城市、门店、区域字眼」 |
| 换一套行业 | 「行业背景改成零售连锁，常用词改成客流、排班、收银」 |
| 减少审查感 | 「禁忌用语加上：是否满足、是否符合、基本入职要求」 |

> **提示**：改「禁忌用语」和「写作指引」往往比只改语气更有效——它们会直接约束 AI 不能说什么、必须怎么组织回复。

### 5.5 保护规则（红线，不能乱删）

保护规则是**硬约束**，违反会导致评估不通过。当前默认包括（节选）：

| 规则要点 | 在防什么 |
|---------|---------|
| 不得编造门店、薪资、排班、福利等事实 | 防止 AI 瞎编具体信息 |
| 兼职场景不得承诺五险一金 | 防止违规承诺 |
| 年龄敏感场景用合规话术，不暴露内部筛选线 | 防止审查感、合规风险 |
| 单轮不要像表单一样连续盘问多个字段 | 防止一次问太多 |
| 首次回复不主动暴露过细薪资、详细地址、完整班次 | 防止信息过载 |
| 不得从语境推断城市；只有证据里明确出现才可提及 | 防止乱说城市/门店 |
| 引导加微信时不得使用门店、城市等地点词汇 | 防止无证据的地点承诺 |

**你可以**：新增一条规则、修改某条规则的表述。  
**不建议**：删除大量或全部保护规则（会触发高危二次确认，且评估很可能不通过）。

示例：

> 加一条保护规则：候选人说「明天下午 3 点有空」时，直接确认该时段，不要反问「是指 3 点之前还是之后」。

### 5.6 事实核查（慎改，有问题找技术）

| 配置项 | 当前默认 | 说明 |
|--------|---------|------|
| 核查模式 | 严格模式 | 没有证据时，尽量不说具体数字/门店/福利 |
| 缺失证据时的兜底 | 给概括性回答 | 不编造、不硬答 |
| 禁止在无证据时承诺的内容 | 具体数字、具体门店、明确福利、具体城市/区域/地址、完整班次列表等 | **不建议运营自行删除这些限制** |

若评估报「事实不符」，通常是**回复说了系统没登记的信息**，应改话术或请技术补门店数据，**不要**通过放宽事实核查来「强行保存」。

---

### 5.7 资格策略与输出护栏（进阶，偶尔改）

**资格策略（以年龄为例）**

| 配置项 | 含义 | 你可以怎么说 |
|--------|------|-------------|
| 不符合时怎么说 | 礼貌说明不合适，不暴露内部标准 | 「年龄不合适时话术再柔和一点」 |
| 信息未知时怎么办 | 先看页面有没有年龄，没有再自然问一句 | 「页面已有年龄就别再问」 |
| 已符合时怎么办 | 不重复追问，直接推进下一步 | 「已知成年就别反复确认」 |

**输出护栏**

| 配置项 | 当前默认 | 你可以怎么说 |
|--------|---------|-------------|
| 单条最多问几个问题 | 精简模式 1 个，聚焦模式 2 个 | 「每条消息最多只问 1 个问题」 |
| 屏蔽的审查感用语 | 是否满足、是否符合、基本入职要求、先确认资格、年龄是否符合 | 「再加屏蔽：入职要求、能不能上岗」 |
| 首条是否禁止具体事实 | 是 | 一般保持开启；有特殊需求先和技术对齐 |

---

### 5.8 修改权限速查

| 类型 | 示例 | 建议 |
|------|------|------|
| ✅ **放心改** | 语气、提问方式、禁忌用语、写作指引、某阶段推进策略、新增保护规则 | 直接对 Agent 描述即可 |
| ⚠️ **能改但要过评估** | 大幅改写多个阶段、清空某阶段禁止行为、改事实核查模式 | 改完务必看预览 + 评估报告 |
| 🚫 **不要自己硬改** | 删除全部保护规则、关掉事实核查、删「禁止无证据承诺城市/门店」类限制 | 找技术同事；这类改动很可能被系统拦截 |
| 🔄 **恢复** | 改错了 / 想回到初始状态 | 「把我的策略全部重置回默认」（高危，二次确认） |

## 六、日常使用（推荐：对话式）

### 打开 Cursor，像跟同事聊天一样说

**示例 1 — 调整语气**

> 帮我把回复语气改得更收敛一些，不要用「很不错」「非常棒」这类过度夸赞的表述。

**示例 2 — 改提问方式**

> 现在一次问太多问题了，改成每次只问一个最关键的问题。

**示例 3 — 先看现状再改**

> 帮我看一下现在的回复策略是什么？我觉得提问方式需要改。

**示例 4 — 确认保存（重要）**

安全评估完成后，Agent 会展示评估报告。**看完报告后**，若满意，请**明确说**：

> 确认保存

或「确认写入」「继续执行写入」。

注意：
- 预览阶段的「可以」「没问题」只表示方向认可，Agent 会自动继续评估
- **只有评估结果展示后**你说的「确认保存」才会触发写入
- 评估通过后 Agent 一定会停下来等你确认，不会自动保存

## 七、一次完整修改会经历什么？

你不需要记步骤，Agent 会自动串联。了解流程有助于你知道「现在卡在哪、还要等什么」：

```
你说需求 → ① 分析影响面 → ② 格式校验 → ③ 效果预览 → ④ 安全评估 → ⑤ 你确认保存 → ⑥ 写入生效
```

### 各阶段你需要做什么？

| 阶段 | 你要做什么 | 说明 |
|------|-----------|------|
| ① 分析影响面 | 不用管 | Agent 分析你的需求涉及策略的哪些模块，**一次性**生成完整修改方案 |
| ② 格式校验 | 不用管 | 检查修改内容是否合法 |
| ③ 效果预览 | **看对比** | 同一条候选人消息，看修改前后回复有什么不同 |
| ④ 安全评估 | **看评估报告** | 自动检查硬规则、事实、质量（约 30s～1.5 分钟） |
| ⑤ 确认保存 | **明确说「确认保存」** | **唯一需要你拍板的环节** |
| ⑥ 写入生效 | 不用管 | 保存成功后，后续自动回复立即用新策略 |

### 为什么能一次到位？

Agent 在生成修改方案前，会**先分析你的需求涉及策略的哪些层面**：

- 人设与语气（persona）
- 各阶段的引导策略（如初次接触、资质确认、岗位咨询）
- 保护规则（硬约束）
- 行业话术模板

分析完成后，**一次性覆盖所有相关模块**，而不是改一个地方试一下、发现不够再改另一个。这样预览一次就能看到完整效果，省掉来回迭代的等待时间。

### 四个容易误解的点

1. **预览满意 ≠ 可以保存**  
   预览只说明「方向可能对」，还必须过安全评估。预览后 Agent 会自动继续评估，不需要你确认。

2. **评估通过后 Agent 会停下来等你确认**  
   Agent 不会评估通过后自己偷偷保存。它会展示评估结果，**等你在下一条消息里明确说「确认保存」**。

3. **评估通过后才能保存**  
   若评估发现问题（如事实不符、触碰红线），需要先调整策略再重新评估，**不能跳过**。

4. **评估超时不用慌**  
   有时服务端计算量大，Agent 会自动减少样本重试。若反复超时，稍后再试或联系技术。

## 八、安全机制（为什么可以放心用）

你的每一次修改都经过多重保护，**不是 Agent 说改就改**：

| 检查项 | 在防什么 | 举例 |
|--------|---------|------|
| 硬规则检查 | 越权承诺、违规表述 | 不能随意承诺薪资、工时等 |
| 事实校验 | 编造不存在的信息 | 回复说「成都有门店」，但系统里没登记成都，会被拦下 |
| 质量评分 | 改完之后反而变差 | 对比修改前后，看回复是否更生硬、更跑题 |
| 版本防冲突 | 多人同时改同一份策略 | 若期间别人也改了，会提示你同步后再保存 |
| 双重确认 | 误操作 | 对话确认 + 系统级确认，高危操作（如重置）还会再问你一遍 |

**评估未通过时**，Agent 会用白话告诉你哪里有问题、建议怎么改。你调整需求后，重新走一遍流程即可。

## 九、常见场景速查

### 场景 A：语气太热情

> 回复太热情了，帮我改成更自然、更克制的语气，不要用「太棒了」「非常不错」这类表述。

### 场景 B：一次问太多

> 现在一次问太多问题了，改成每次只问一个最关键的问题。

### 场景 C：特定情况下的回复方式

> 加一条规则：候选人说具体时段有空的时候，直接确认覆盖就行，不要反问「是指 X 之前还是之后」。

### 场景 D：先看看现在什么样

> 帮我看一下现在的回复策略是什么。

### 场景 E：改错了，想恢复

> 把我的策略全部重置回默认。

（重置会删掉所有自定义，恢复系统默认，属于高危操作，会要求你二次确认。）

### 场景 F：管理员帮同事改策略

使用 Admin Token 后，先告诉 Agent 要改哪位运营同事的策略，例如：

> 帮我改一下张三的回复策略，语气收敛一点。

之后流程与个人改策略相同。

### 场景 G：改行业话术库

> 在行业话术库里，禁忌用语加上「太棒了」「非常不错」；写作指引加一条：不要用过度夸赞的语气。

### 场景 H：改常用行业词和风格

> 行业背景改成「零售连锁，强调就近上班和弹性排班」，常用词加上「提成」「保底」，风格关键词要「亲和、耐心」。

## 十、常见问题

### 修改后多久生效？

写入成功后**立即生效**。之后所有自动回复都会使用新策略。

### 改错了怎么办？

两种方式：

1. **再改回来** — 走一遍完整修改流程，把策略调回去  
2. **重置为默认** — 说「重置策略」，会恢复系统初始配置  

每次修改都有审计记录，技术同事可以协助追溯。

### 「事实不符」是什么意思？

修改后的回复里提到了**系统里没有登记的信息**。

**例子**：策略生成的回复说「我们在成都和重庆都有门店」，但系统里只登记了成都，就会被判定为事实不符。

**怎么办**：

- 调整策略措辞（不要说系统里没有的门店/信息）  
- 或联系技术同事补充门店/绑定数据后，再重新评估保存  

### 评估超时了怎么办？

Agent 会自动减少评估样本重试。若反复超时：

1. 等几分钟再试（可能是服务端繁忙）  
2. 联系技术，附上 `diagnostic_status` 的输出  

**注意**：评估超时**不能**跳过评估直接保存，这是安全防线。

### 预览时说了「可以」「没问题」，为什么还没保存？

预览阶段的「可以」只表示你**认可修改方向**，不等于授权保存。  
Agent 会继续自动做安全评估，评估完成后展示结果，**等你再次明确说「确认保存」**才会写入。

整个流程是：预览（你说"可以"）→ Agent 自动做评估 → 展示评估报告 → **你说"确认保存"** → 写入。中间不会跳步。

### 我是管理员，怎么改别人的策略？

确保使用 Admin Token。对话时先说明要改哪位运营同事，Agent 会引导你选择，之后按正常流程操作。

### 对话里需要说技术术语吗？

不需要刻意说技术术语。patch、API 等词用日常中文描述即可，例如「语气」「提问方式」「保护规则」。tenantId（运营人员标识）可以在选择/确认操作对象时展示。
