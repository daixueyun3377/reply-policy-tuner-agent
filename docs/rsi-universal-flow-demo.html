终极目标与落地路线

模型自我优化平台

让业务 Agent 在证据门禁下持续自我优化:早期人工评审每一次优化,后期随评估器被验证可信,逐步把"发布决策"自动化。核心安全前提是——优化循环永远无权修改自己的评判标准。

北极星(终极目标): 一个多 Agent 共享的持续自我优化平台。模型负责"发现问题 → 提出优化 → 验证 → 发布",人介入的程度随评估能力成熟而递减;但"评判标准"始终由独立、冻结、人治理的评估体系把控,优化循环绝不能改自己的考卷。

1. 通用主流程:持续自我优化闭环

所有业务 Agent 共用同一条改进生命周期。差异在于每个 Agent 的样本、问题类型、候选优化、评估方式和发布门禁不同。

1
Observe(观察)
收集证据链
  • 用户反馈
  • 模型输出
  • 人工改写
  • 评估结果
2
Diagnose(诊断)
发现和归因问题
  • 失败聚类
  • 问题归因
  • 影响面分析
3
Propose(提出候选)
生成 Candidate
  • 策略补丁
  • 提示词补丁
  • 回归样本
4
Evaluate(评估)
独立评估器验证
  • 确定性校验
  • 独立判卷模型
  • 回归对比
5
Decide(决策)
人工→规则,逐步自动
  • 接受
  • 拒绝
  • 修订
6
Release(发布)
通过业务门禁上线
  • 策略写入
  • Prompt 更新
  • 带审计+可回滚
7
Observe Again(再观察)
用真实结果验证
  • 灰度/holdout
  • 正向收益
  • 负向回归→回滚
发布后效果回流到 Observe,形成下一轮优化。注意:Evaluate 与 Observe Again 才是闭环可信度的上限——评估器有多可信,才敢把决策自动化到什么程度。

2. 三模型架构:干活 / 出题 / 判卷分离

"模型自我优化"不靠同一个模型自评自改,而是把角色拆给不同模型,并让评判锚定在模型之外的客观信号上。

Worker(干活模型) 在 Agent 上真实服务

生成回复 / 策略候选 / SQL。它是被优化的对象,不参与给自己打分。

Examiner(出题模型) 构造评估用例

从真实生产失败中抽取并扩展测试集。合成题只能补充、不能替代真实流量。

Judge(判卷模型) 独立评分

最好与 Worker 不同家族,避免共享盲区。rubric 冻结,优化循环无权修改。

分三个模型 ≠ 自动独立。

若三者同源(同一基座),它们共享盲区,会一起犯同样的错——三道防线其实是同一道墙刷了三遍。真正的独立性由下一节的四条铁律保证。

3. 四条独立性铁律(不可侵犯)

这是整个方案的安全主轴。少任何一条,自我优化就会退化成"考生自己改答案",且退化得更隐蔽。

① 判卷与干活不同源
Judge 模型尽量与 Worker 不同家族/不同厂商,让两者盲区错开。
② 评判之上压着确定性校验
事实门禁、SQL 执行、schema/lint 是代码不是意见,模型改不动,优先级高于判卷模型。
③ 出题锚定真实流量
测试集持续从真实生产失败抽取,并保留人工维护的回归核心集,防止考卷脱离现实。
④ 判卷标准冻结且循环改不动
rubric / 判卷 prompt 冻结,只能由独立治理流程升级,优化循环无权修改。
最终仲裁永远是线上真实结果。

判卷模型再独立也只是"意见",可被哄、会漂移。holdout / 灰度回流的真实业务指标才是模型造不了假的终审。

4. 两个"测谎"指标(自动化后长期盯)

一旦把决策交给自动化,用这两个指标监控评估器有没有在自欺。任一掉线,立即降自主度、回退人工评审。

指标含义掉线意味着
判卷模型 vs 人工抽检 一致率判卷意见和人类判断是否对齐判卷在漂,标准失真
判卷分数 vs 线上真实指标 相关性分数涨是否真的带来现实收益在刷分不刷现实(reward hacking)

5. 自主度阶梯

自动化的是"发布决策",不是"评判标准"。评判标准这一列从头到尾都不在优化循环手里——这就是安全的关键。

等级自动化的是什么谁拍板发布评判标准由谁控前提
L1(现状)候选生成人逐条评审独立评估器 + 人—
L2候选 + 回归门禁人批发布独立评估器评估器初步可信
L3低风险改动自动发布 + 监控回滚规则,人事后审同一独立冻结评估器测谎指标稳定 + 回滚机制
L4高风险也自动规则独立评估器,rubric 由治理流程单独升级长期验证 + 完善治理
原则:评估器有多可信,就放多少权。评估信号弱的 Agent(如话术语气/转化)长期停在 L1–L2,不要用不可靠的尺子去自动放大改动。

6. 三阶段路线图

Phase 1 · 现在 reply-policy 单 Agent 闭环做扎实
  • 确立 L1,跑通 L2
  • 补迭代历史持久化
  • 补发布后观察(灰度/holdout)
  • 建立独立判卷 + 冻结 rubric
Go/No-Go:闭环稳定产出可信改进,可审计、可回滚
Phase 2 · 下一步 复制到 wechat-reply
  • 检验"统一生命周期"能否真复用
  • 主攻话术评估器弱的问题
  • 真实评估"通用化"假设
Go/No-Go:第二个 Agent 评估器达标,复用收益被验证
Phase 3 · 远期(有条件) 提升自动化 / 接入更多 Agent
  • 评估器成熟后推进 L3
  • nl2sql 等新 Agent 视情况接入
  • A2A 仅在多 Agent 成熟后再评估
前置条件:测谎指标长期稳定 + 多个成熟 Agent

7. 明确的边界(本期不做)

不做原因
A2A(Agent 间互相学习)只有 1.x 个成熟 Agent,跨域知识能否复用未经验证,现在投入是浪费。作为远期有条件选项。
优化循环修改自己的评判标准等于考生自己改答案,直接摧毁可信度。rubric 变更走独立治理流程。
全自动发布(评估器不达标的 Agent)用不可靠的评估自动放大改动,风险最大。
宣称"模型自我进化/越用越聪明"名不副实且制造错误预期。我们做的是证据门禁下的受控持续优化。
一句话总结。

愿景是"模型自我优化、人越来越少介入";安全底座是"无论自动化到哪一级,评判标准始终独立、冻结、由人治理,优化循环永远改不动自己的考卷"。
